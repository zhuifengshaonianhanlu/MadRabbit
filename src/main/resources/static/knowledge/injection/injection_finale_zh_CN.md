### 第一关：SQL注入 - 登录绕过
**核心知识点：**
- SQL注入的工作原理：用户输入被拼接到SQL语句中
- 认证绕过的常见技巧：`' OR '1'='1`、`admin' --`
- 观察SQL语句的构造方式

**攻击路径分析：**
```
1. 发现登录表单 → 用户名和密码输入
2. 分析SQL语句结构 → WHERE username='x' AND password='y'
3. 构造注入Payload → admin' OR '1'='1' --
4. 绕过密码验证 → 以admin身份登录
```

**防护建议：**
```java
// 错误示例 - 字符串拼接
String sql = "SELECT * FROM users WHERE username='" + username + "' AND password='" + password + "'";

// 正确示例 - 参数化查询
PreparedStatement stmt = conn.prepareStatement(
    "SELECT * FROM users WHERE username=? AND password=?"
);
stmt.setString(1, username);
stmt.setString(2, password);
```

**关键启示：**
永远使用参数化查询，不要将用户输入直接拼接到SQL语句中。

### 第二关：SQL注入 - 数据泄露
**核心知识点：**
- UNION注入的工作原理：合并两个查询的结果
- 信息收集技巧：获取表名、列名
- 敏感数据提取

**攻击流程分析：**
```
1. 确认注入点 → 搜索功能
2. 判断列数 → ' UNION SELECT 1,2,3,4--
3. 确认回显位置 → 哪些列会显示在页面上
4. 提取敏感数据 → ' UNION SELECT id,name,email,role FROM secrets--
```

**防护建议：**
```java
// 输入验证 - 白名单
if (!keyword.matches("^[a-zA-Z0-9\\u4e00-\\u9fa5\\s]+$")) {
    throw new IllegalArgumentException("Invalid search keyword");
}

// 最小权限 - 数据库账户权限限制
GRANT SELECT ON app_db.public_data TO 'app_user'@'localhost';
-- 不要授予访问敏感表的权限
```

**关键启示：**
UNION注入可以跨表查询，需要严格限制数据库账户权限，并对所有用户输入进行验证。

---

### 第三关：命令注入
**核心知识点：**
- 命令注入的工作原理：用户输入被传递给系统命令
- 命令分隔符：`;`、`|`、`&&`、反引号、`$()`
- 危险的系统调用函数

**攻击流程分析：**
```
1. 识别可能的命令执行点 → ping功能
2. 分析命令构造方式 → ping -c 3 {用户输入}
3. 构造注入Payload → 127.0.0.1; cat /etc/passwd
4. 执行额外命令 → 读取敏感文件
```

**防护建议：**
```java
// 危险示例 - Runtime.exec(String)
Runtime.getRuntime().exec("ping -c 3 " + userInput);

// 安全示例 - ProcessBuilder + 输入验证
if (!host.matches("^[0-9]{1,3}(\\.[0-9]{1,3}){3}$")) {
    throw new IllegalArgumentException("Invalid IP");
}
ProcessBuilder pb = new ProcessBuilder("ping", "-c", "3", host);
```

**关键启示：**
命令注入可以完全控制服务器。尽量避免调用系统命令，如果必须调用，务必使用参数数组而非字符串拼接。

## 🛡️ 注入攻击防护最佳实践

### 1. SQL注入防御
| 防御措施 | 重要性 | 说明 |
|---------|-------|------|
| 参数化查询 | ⭐⭐⭐⭐⭐ | 最有效的防御手段 |
| 输入验证 | ⭐⭐⭐⭐ | 白名单优于黑名单 |
| 最小权限 | ⭐⭐⭐⭐ | 限制数据库账户权限 |
| 错误处理 | ⭐⭐⭐ | 不要暴露SQL错误信息 |
| WAF | ⭐⭐⭐ | Web应用防火墙作为补充 |

### 2. 命令注入防御
| 防御措施 | 重要性 | 说明 |
|---------|-------|------|
| 避免系统调用 | ⭐⭐⭐⭐⭐ | 使用语言内置函数替代 |
| 参数数组 | ⭐⭐⭐⭐⭐ | 使用ProcessBuilder等安全API |
| 输入验证 | ⭐⭐⭐⭐ | 严格验证用户输入格式 |
| 沙箱环境 | ⭐⭐⭐ | 限制命令执行的环境 |
| 最小权限 | ⭐⭐⭐ | Web服务器以低权限用户运行 |

## 💡 两种注入类型对比

| 特性 | SQL注入 | 命令注入 |
|------|---------|----------|
| 攻击目标 | 数据库 | 操作系统 |
| 影响范围 | 数据泄露、篡改 | 服务器控制 |
| 利用难度 | 相对简单 | 相对简单 |
| 危害程度 | 高 | 极高 |
| 主要防御 | 参数化查询 | 避免命令执行 |
| 常见场景 | 登录、搜索、表单 | 系统工具、文件操作 |
