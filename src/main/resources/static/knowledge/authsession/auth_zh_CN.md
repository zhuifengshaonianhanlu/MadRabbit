# 🚪 实验手册：认证与会话安全

### 0. 序言
在 Web 的世界里，服务器就像一个患有“超短期记忆丧失症”的保安。每一分钟他都会忘记你是谁。

*   **认证 (Authentication)**：是你向保安证明“我是谁”的过程（通常靠账号密码）。
*   **会话 (Session)**：是保安看完你身份证后，发给你的一张临时出入证（Cookie 或 Token）。

本章练习的目标很简单：**要么让保安认错人，要么伪造那张出入证。**

---

### 1. 暴力破解：只要功夫深，铁杵磨成针
**原理简介**：
如果一个登录接口没有验证码、没有频率限制、没有 IP 锁定，那么它就不叫登录接口，它叫“密码验证 API”。只要黑客的字典够大，你的服务器就是他的家。

**冷知识**：
大部分用户的密码强度，基本取决于他们家宠物的名字或者是 `123456`。

**避坑指南**：
不要相信前端验证。在 JavaScript 里限制输入频率，就像在自家门口贴一张“请不要连续敲门”的纸条，除了显得你很萌以外，没有任何防御作用。

---

### 2. 用户枚举：你猜他在不在？
**原理简介**：
当用户登录失败时，如果你的后端返回：
*   `404 - 用户不存在`
*   `401 - 密码错误`

恭喜你，你正在免费为黑客提供“全站合法用户名单查询服务”。

**冷幽默**：
好的程序员应该学会说谎。无论谁来，统一回复：“用户名或密码错误”。这种模糊美学不仅能保护隐私，还能让黑客气到砸键盘。

---

### 3. 会话固定 (Session Fixation)：借刀杀人
**原理简介**：
服务器太懒，在用户登录前就发了一个 `JSESSIONID`，登录后居然还接着用同一个。

**攻击剧本**：
1. 我先去官网领一个 ID（比如 `ABC`）。
2. 我把 `http://target.com/?jsessionid=ABC` 发给受害者（或者通过诱导设置其 Cookie）。
3. 受害者登录了。
4. 既然 ID 没变，现在我手里这个 `ABC` 也就自动升级成受害者的“出入证”了。

**核心思想**：
你不换证，我就当你没走。

---

### 4. 弱会话标识：Base64 并不是加密
**原理简介**：
有些开发者觉得 `JSESSIONID` 太难记，喜欢自己造。
比如：`Cookie: user_id=admin`。
或者是：`Cookie: user_id=YWRtaW4=`（这只是 admin 的 Base64，不叫加密，叫翻译）。

**讽刺点**：
如果你能通过修改 Cookie 里的一个数字就变成管理员，那这个安全架构的水平大概和“防君子不防猴子”差不多。

---

### 5. JWT 的“算法之虚”
**原理简介**：
JWT (JSON Web Token) 很流行，但也给了人类更多犯错的机会。
*   **None 算法**：黑客把 Header 里的 `alg` 改成 `none`，后端如果不校验，就会直接信任这个 Token。
*   **弱密钥**：如果你的签名密钥是 `123456`，那黑客只需要 0.01 秒就能反推出来，然后给自己封个“超级管理员”。

**警示**：
JWT 就像一封信，虽然封了口，但如果信封是透明的且封印是用口水粘的，那谁都能改。

---

### 6. 逻辑漏洞：忘记密码的“后门”
**原理简介**：
有些系统在重置密码时，会问你：“你叫什么？”
当你回答“admin”后，它直接返回：“好的，验证码发到你邮箱了。顺便，这是你的新密码重置链接：`.../reset?user=admin`。”

**操作指南**：
在这些关卡里，请仔细盯着每一个 HTTP 响应包。有时候，密码或者是重置链接就藏在服务器“不小心”多说的那句话里。

---

### 7. 结语
认证安全的核心只有一句话：**永远不要信任客户端传来的任何关于“我是谁”的声明，除非你已经用最严苛的逻辑验证过它。**

现在，去靶场试试看。如果你进不去，那是正常的；如果你进去了，说明那个“保安”该下班了。
