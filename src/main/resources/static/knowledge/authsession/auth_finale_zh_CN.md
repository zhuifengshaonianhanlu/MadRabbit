### 第一关：弱密码破解 - 暴力破解攻击
**核心知识点：**
- 暴力破解的原理：通过穷举法尝试所有可能的密码组合
- 系统存在的安全缺陷：
  - 无验证码保护
  - 无登录频率限制
  - 无账户锁定机制
  - 无 IP 封禁策略

**防护建议：**
```javascript
// 前端防护（不够安全）
if (attempts > 3) {
    showCaptcha();
}

// 后端防护（必须实现）
1. 实施登录频率限制（如：5次/分钟）
2. 添加图形验证码或滑动验证
3. 账户锁定机制（连续失败5次锁定15分钟）
4. 强密码策略（长度、复杂度要求）
5. 密码强度检测和提示
```

**关键启示：**
永远不要依赖前端验证，真正的安全必须在后端实现。

### 第二关：任意密码重置 - 逻辑漏洞
**核心知识点：**
- 密码重置流程中的验证逻辑缺失
- 常见的逻辑漏洞类型：
  - 验证码可预测或绕过
  - 用户身份验证不严
  - 重置链接泄露
  - 响应信息泄露敏感数据

**攻击路径分析：**
```
1. 获取重置验证码 → 通过响应包或逻辑绕过
2. 构造重置请求 → 修改目标用户参数
3. 完成密码重置 → 绕过身份验证
```

**防护建议：**
```python
# 安全的密码重置流程
def reset_password(user_email, verification_code, new_password):
    # 1. 严格的验证码校验
    if not validate_code(user_email, verification_code):
        return "验证码错误或已过期"
    
    # 2. 验证码一次性使用
    mark_code_as_used(verification_code)
    
    # 3. 统一的错误提示
    # 不要区分"用户不存在"和"验证码错误"
    
    # 4. 记录操作日志
    log_password_reset(user_email, request.ip)
    
    # 5. 通知用户
    send_email(user_email, "密码已重置，如非本人操作请立即联系客服")
```

**关键启示：**
每一个"方便用户"的功能，都可能成为攻击者的"方便之门"。

### 第三关：JWT 令牌安全 - 弱密钥爆破
**核心知识点：**
- JWT (JSON Web Token) 的工作原理
- JWT 的三部分结构：Header.Payload.Signature
- HS256 对称加密算法的密钥安全要求

**攻击流程：**
```
1. 获取合法 JWT Token
2. 提取 Token 结构（Base64 解码）
3. 离线爆破签名密钥
   - 使用常见弱密钥字典
   - 使用 Hashcat 等工具加速
4. 伪造目标用户的 JWT
5. 使用伪造 Token 访问受保护资源
```

**防护建议：**
```java
// JWT 安全配置
public class JwtSecurityConfig {
    // 1. 使用强密钥（至少 256 位）
    private static final String SECRET_KEY = 
        "your-very-long-and-complex-secret-key-at-least-32-characters";
    
    // 2. 或使用非对称加密（RS256）
    // 私钥签名，公钥验证，更安全
    
    // 3. 设置合理的过期时间
    private static final long EXPIRATION = 3600000; // 1小时
    
    // 4. 敏感操作需要二次验证
    // 不要完全依赖 JWT 进行权限判断
}
```

**关键启示：**
JWT 的安全性完全依赖于签名密钥的强度。一旦密钥泄露或被破解，攻击者可以伪造任意用户的身份。

## 🛡️ 认证与会话安全最佳实践

### 1. 多层防御策略
```
第一层：强密码策略
第二层：多因素认证 (MFA)
第三层：登录频率限制
第四层：异常行为检测
第五层：会话管理
第六层：审计日志
```

### 2. 密码安全
- ✅ 最小长度 8 位，建议 12 位以上
- ✅ 包含大小写字母、数字、特殊字符
- ✅ 使用 bcrypt/Argon2 等慢哈希算法存储
- ✅ 定期提醒用户更换密码
- ❌ 明文存储密码
- ❌ 使用 MD5/SHA1 等快速哈希
- ❌ 在响应中返回密码信息

### 3. 会话管理
- ✅ 登录后生成新的 Session ID
- ✅ 设置合理的会话超时时间
- ✅ 使用 HTTPS 传输 Cookie
- ✅ 设置 HttpOnly 和 Secure 标志
- ❌ 在 URL 中传递 Session ID
- ❌ 使用可预测的 Session ID

### 4. JWT 安全
- ✅ 使用强密钥（256 位以上）
- ✅ 考虑使用 RS256 非对称加密
- ✅ 设置合理的过期时间
- ✅ 实施 Token 刷新机制
- ❌ 在 JWT 中存储敏感信息
- ❌ 使用弱密钥或默认密钥
- ❌ 忽略算法验证

### 5. 密码重置安全
- ✅ 使用加密安全的随机验证码
- ✅ 验证码一次性使用且有时效
- ✅ 严格的用户身份验证
- ✅ 记录所有重置操作日志
- ✅ 通知用户密码已重置
- ❌ 在响应中返回重置链接
- ❌ 使用可预测的验证码
- ❌ 允许验证码重复使用

## 💡 核心思想总结

通过这些关卡的学习，你应该深刻理解了认证与会话安全的核心原则：

### 1. 永远不要信任客户端
```
所有的用户输入都是不可信的：
- 用户名、密码、验证码
- Cookie、Header、Token
- 任何来自客户端的数据
```

### 2. 防御深度原则
```
单一的安全措施是不够的：
- 前端验证 + 后端验证
- 频率限制 + 验证码
- 密码强度 + 多因素认证
- 会话管理 + 异常检测
```

### 3. 最小权限原则
```
只授予必要的权限：
- 普通用户不需要管理员权限
- 短期会话不需要长期有效
- 单次操作不需要持久凭证
```

### 4. 安全默认原则
```
默认应该是安全的：
- 默认启用 HTTPS
- 默认要求强密码
- 默认启用频率限制
- 默认记录审计日志
```
